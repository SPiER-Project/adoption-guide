## C. Structural & Architectural Rot

### C1. The gate estate is half the size of the product, and its knowledge lives in a 60 KB CLAUDE.md that the gates cannot check

- **Historical artifact:** every shipped defect got a bespoke `scripts/check-*.mjs` plus a ⚠️ block in CLAUDE.md. `scripts/` is now 17,144 LOC against roughly 34,000 LOC of app + package source; CLAUDE.md is 827 lines with 76 ⚠️ blocks. `docs/plans/structure-simplification-scope.md` diagnosed this at 8.5k LOC on 2026-08-28 and proposed "derive, don't check"; the estate has doubled since.
- **Current dysfunction:** every structural move (web → apps, the CDS split) rots N gate comments and M doc paragraphs, and the one gate built for that class, `check-md-paths`, derives its prefixes from the *current* tracked tree. The deleted `web/` root, the exact event the gate was written after, is therefore invisible: **45 backticked `web/src/…` paths in live docs pass ✓**, including CLAUDE.md's own instructions. CLAUDE.md also contradicts itself on `IS_DEMO` (lines 82, 102, 688).
- **Remediation:** (1) D7, the retired-roots set in `check-md-paths`, closes the hole in one line. (2) Honour CLAUDE.md's own stated design ("states the rule and links here"): move each ⚠️ rationale paragraph into the `docs/internals/` file the section already links, leaving rule + link (target under 300 lines). (3) Execute the "derive" phases already scoped: stage ids and LOINC / disposition codes as `*.generated.ts` from FSH via `copy-fhir.mjs` (precedent: `care-plan-profiles.generated.ts`), retiring `check:stages` and the hand-duplication warnings with it.

### C2. Four hand-mirrored Worker toolchains, already drifting

- **Historical artifact:** #387 "no npm workspaces" gave one root install; the cost was copying tooling into each service. `services/{cds,guide,clinical,mock-ehr}` carry eslint configs (3 byte-identical + 1), tsconfigs (two identical pairs), vite configs (cds ≡ guide, including an alias cds never uses) and .gitignores (cds ≡ guide, with a stale `web-dist/`).
- **Current dysfunction:** the versions have forked: eslint 10 in services vs 9 at root, vitest 3 vs 4, `@types/node` 22 vs 24, wrangler `~4.107` in two services vs `^4.0.0` in the other two, while the `//wrangler` note says the opposite. Fresh installs hit ERESOLVE, and security fixes (B, row 3) sit behind a pin only two of four honour. Services also lack the `noUnusedLocals` / `noUnusedParameters` every app tsconfig has.
- **Remediation:** (1) `packages/worker-tooling/` exporting `workerEslintConfig`, `tsconfig.worker.json` and `workerViteConfig(entry, aliases)`; each service config becomes a three-line import. (2) D6, a parity gate so the four manifests must agree with each other. (3) D10, Dependabot groups so they move together.

### C3. Domain helpers duplicated by copy, and one FHIR builder living in the UI package

- **Historical artifact:** the stage-5/6/7 builders were each written in one PR and copied the neighbour's helpers. `displayFor` is byte-identical in 4 files; `stageTag` in 5 (4 identical, and `riskEpisode.ts:194` with a hardcoded display string instead of `STAGE_TITLE`, the exact drift copying invites); `effectiveOf` ×2, `toggle` ×2, `InclusionBadge` ×2 across the two apps, `describeError` ×2 (app-shell vs core/writeback).
- **Current dysfunction:** `packages/tool-views/src/lib/lethalMeans.ts` builds the TL-008 Procedure / Observation resources inside the UI package, the only FHIR writer outside `packages/core`, which is why its `effectiveOf` is a copy of `cdsHooks/problemListCard.ts` and its test sits in root `tests/`. `check:core-boundary` keeps React out of core; nothing keeps domain logic out of tool-views.
- **Remediation:** (1) `packages/core/src/lib/stage.ts` exporting `stageTag(stageId)` + `displayFor` (+ `CodedOption`), replacing nine copies. (2) `git mv` `lethalMeans.ts` and its test into core; it already imports only core. (3) `InclusionBadge` becomes a `Pill` variant in `packages/ui`. (4) D5, a jscpd gate so copies fail CI.

### C4. Two production hosts for one guide SPA, personal origins baked into source, deploy scripts that cannot produce a correct artifact locally

- **Historical artifact:** GitHub Pages came first (base `/adoption-guide/`); Cloudflare Workers came for the CDS API and the CSP; both are declared "not legacy" and both render the IG on every push through a 717-line `deploy.yml` with five jobs.
- **Current dysfunction:** `VITE_BASE` env-switching, a `public/_headers` one host ignores, and `*.bbthorson.workers.dev` hardcoded in nine places across seven source files (`packages/worker-http/src/spaAssets.ts:39`, `packages/core/src/lib/cdsHooks/endpoint.ts:21`, `apps/guide/src/data/surfaces.ts:34`, `services/mock-ehr/src/app.ts:112,131`, `services/mock-ehr/src/smart.ts:96–97`, `services/cds/wrangler.jsonc:33,46`). `services/guide` `npm run deploy` ships a Worker whose `/ig/*` 404s because only CI stages the render; CLAUDE.md documents the trap instead of removing it.
- **Remediation:** (1) make `deploy` in `services/guide` and `services/clinical` refuse to run outside `CI=true`. (2) One `deploy-origins.json` per environment, read by wrangler vars and by the four modules above, so an origin change is one edit; this is independent of the DNS blocker. (3) Decide whether Pages becomes a redirect to the Worker (the only host that can serve `/ig/` behind a CSP) and delete the second base path.

### C5. The mock EHR is a second front-end codebase written in template strings

- **Historical artifact:** "deliberately not styled like SPiER" (a demo claim) grew into its own token system (`hostChrome.ts`, 712 lines of CSS-in-TS with its own gate `check:host-css`), its own vanilla-JS UI (`chartPage.ts`, 1,111 lines, of which `chartScript` is a 371-line JS template literal), and one Hono `app.ts` of 1,084 lines and 29 routes mixing CORS, SMART auth, FHIR read/write, FHIRcast and admin. `services/mock-ehr/src` is 5,888 LOC, larger than `apps/guide`.
- **Current dysfunction:** the inline script is a string: no tsc, no eslint and no vitest can see it, which is how the `innerHTML` concatenation (B, row 11) exists. Every panel-behaviour change is an edit inside a template literal.
- **Remediation:** (1) `app.route()` split into `routes/fhir.ts`, `routes/smart.ts`, `routes/fhircast.ts`, `routes/admin.ts`. (2) `chartScript` becomes `src/client/chart.ts`, a second Vite entry emitted as a static asset and referenced by `<script src>`, still framework-free, now typed and testable. (3) Replace concatenation with DOM builders. Keep `hostChrome.ts` as is; its gate is sound.
